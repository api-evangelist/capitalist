# Capitalist

> Capitalist (https://capitalist.net) is a payment platform for mass payouts and
> multi-rail money collection. One funded account pays out to cards, bank
> transfers, mobile operators, fast payment systems, e-wallets and
> cryptocurrencies across the CIS region, Latin America, Asia and Africa without
> the payer opening an account with each underlying system.

## Which API

Capitalist runs two API generations at once.

- **Integration API (v2) — current.** Base URL `https://api2.capitalist.net`,
  routes prefixed `/v1/`. JSON over HTTPS. Documented at
  https://docs.capitalist.net/api/integration-api.html (last updated
  2026-07-16). This is the one to build against.
- **Payments API (v1) — deprecated.** Base URL `https://api.capitalist.net`.
  A single POST endpoint where an `operation` form field selects the call.
  The provider has moved its documentation to
  https://capitalist.net/developers/deprecated/v1/api. It is still serving
  (self-reports version 1.9.8) but no sunset date is published.

## Authentication (v2)

Three headers on every request:

- `API-Key` — created at https://capitalist.net/security. Requires API access
  enabled and Google 2FA active on the account.
- `X-Request-Timestamp` — current time in epoch milliseconds.
- `Signature` — `sha256_hex(X-Request-Timestamp + raw request body + API secret)`.

No OAuth, no OIDC, no scopes. Access can additionally be restricted to an IP
allowlist. An unauthenticated call returns HTTP 401 with the plain-text body
``Missing `API-Key` ``.

## Endpoints (v2)

Accounts and rates
- `GET /v1/account/list?currency=USD` — balances per account
- `GET /v1/rate?from=USD&to=EUR` — bare JSON number
- `POST /v1/exchange` — convert between your own accounts; returns null

Payments
- `POST /v1/payment` — create a payout; returns `{ "documentId": <int64> }`
- `GET /v1/payment/document/{documentId}` — status by server id
- `GET /v1/payment/{userRequestId}` — status by your id

Reporting
- `GET /v1/orders` — merchant orders (limit/offset, ISO 8601 period filters)
- `GET /v1/transactions` — ledger entries (limit/offset, period filters)

Cryptocurrency
- `GET /v1/depositAddress/{currency}` — BTC, ETH, USDT, USDTt, USDTb, USDC, USDCb
- `GET /v1/depositAddressAutoUSDTt/{account}` — USDT TRC-20 with autoconversion

KYC
- `POST /v1/kyc/start`, `GET /v1/kyc/status/{kycExternalUserId}/{sort}`,
  `GET /v1/kyc/statusByUuid/{uuid}`, `POST /v1/kyc/setData/{uuid}`,
  `POST /v1/kyc/setPicture/{uuid}/{type}`, `POST /v1/kyc/confirm/{uuid}`

Security
- `GET /v1/whitelist`, `POST /v1/whitelist`, `POST /v1/whitelist/remove`

## Things an agent must know before calling this API

- **Payouts are irreversible.** There is no cancel, void, refund or reverse
  operation anywhere in the surface. A payment reaches `EXECUTED` or `DECLINED`
  and stays there. Payment return is a manually priced support service, not an
  API call.
- **Idempotency is partial.** `userRequestId` on `POST /v1/payment` is the only
  duplicate guard the provider documents, and it covers that one operation.
  `POST /v1/exchange` — which moves money — has none.
- **There is no sandbox.** No test host, no test key prefix, no fixture data.
  The provider's own advice is to "test with small amounts first" against
  production.
- **The payment channel decides the required fields.** `payload.type` picks one
  of ~45 channel schemas (RUCARD, PAYONEER, SBP, BITCOIN, ...) and each has its
  own required recipient fields. Not all documented channels are guaranteed to
  be available.
- **Errors are free text.** `{ "error": "..." }` with HTTP 400. No stable error
  codes and no decline-reason taxonomy behind `state: DECLINED`.
- **Currency codes are not pure ISO 4217.** `RUR` (not RUB) for the rouble, and
  `USDT`/`USDTt`/`USDTb`/`USDC`/`USDCb` distinguish ERC-20, TRC-20 and BEP-20.
- **Amounts are decimal major units** (100.00 USD), not minor units.
- **Crypto deposit addresses expire.** Valid for at most 8 hours; do not cache.
- **Poll under 20 times a minute**, or register a `callbackUrl` and consume the
  signed callback instead.

## Client code

Capitalist publishes no package on any registry. First-party code is
clone-only from https://github.com/capitalist-net:

- `API-V2` — Java client for the current v2 API, generated from the provider's
  own `Integration+API.json` by openapi-generator 7.14.0, plus a hand-written
  request signer and three runnable examples.
- `php-api-samples` — PHP client for the deprecated v1 API (composer.json
  declares 2.8.0 but the package is not on Packagist).
- `api-examples`, `docs` — C#/.NET snippets for v1.
- `Capitalist-API-Java-crypto` — v1 password encryption and signing, last
  pushed 2016.

## Not published

No MCP server. No A2A agent card. No GraphQL. No AsyncAPI. No gRPC or SOAP
contract. No `/.well-known/` document of any kind on any Capitalist host. No
status page, no SLA, no dated API changelog, no public Postman collection.
